MESSI — cara pasang di cPanel
==============================

Butuh PHP 8.0 ke atas. Kalau hostingnya masih PHP 7, halamannya akan bilang sendiri
dan memberi tahu cara gantinya. Ganti dulu sebelum lanjut:
cPanel -> Software -> Select PHP Version (atau MultiPHP Manager) -> pilih 8.1 / 8.2.


0. CEK DULU HOSTINGNYA SANGGUP ATAU TIDAK
   Setelah langkah 3 (upload), buka:  https://namadomain.com/messi/cek.php
   Halaman itu memeriksa versi PHP, ekstensi yang dibutuhkan, koneksi database,
   tabel, HTTPS, base_url, dan apakah hosting ini boleh menghubungi Google Chat.
   Setiap yang kurang disebutkan beserta cara membetulkannya, dan di bawahnya ada
   perintah cron yang sudah jadi untuk hosting ini.

   Buka lagi tiap selesai satu langkah. Kalau sudah hijau semua, selesai.
   Setelah akun admin dibuat, halaman ini minta login admin dengan sendirinya.
   Boleh dihapus kalau sudah tidak dipakai.


1. BUAT DATABASE
   cPanel -> MySQL Databases
   - Create New Database: messi
   - Add New User: bikin user + password (simpan passwordnya)
   - Add User To Database: pilih keduanya -> centang ALL PRIVILEGES -> Make Changes
   Catat tiga nama yang jadi, semuanya berawalan nama akun cPanel, contoh:
     database : akunanda_messi
     user     : akunanda_messi
     password : (yang tadi dibuat)


2. BUAT TABELNYA
   cPanel -> phpMyAdmin -> klik database tadi di kiri -> tab Import
   -> Choose File: install.sql -> Go
   Harus muncul tujuh tabel: users, sessions, login_tokens, cycles, commitments,
   job_log, settings

   SUDAH PERNAH PASANG VERSI SEBELUMNYA?
   Upload dulu berkas barunya (langkah 3), lalu masuk sebagai admin dan buka
   "Pemutakhiran database" dari halaman Orang & tim. Satu tombol, dan dia yang
   mengurus tabel maupun kolom yang kurang. Data yang sudah ada tidak dihapus,
   dan menjalankannya dua kali tidak melakukan apa-apa pada kali kedua.
   (Import ulang install.sql lewat phpMyAdmin juga aman, tapi tidak cukup
   sendirian: kolom baru di tabel yang sudah ada tidak ikut terbuat.)


3. UPLOAD
   cPanel -> File Manager -> masuk ke public_html
   - buat folder: messi
   - masuk ke folder itu -> Upload -> pilih messi-cpanel.zip
   - setelah selesai, klik kanan zip-nya -> Extract
   - hapus zip-nya

   Pastikan "Show Hidden Files" aktif (Settings di kanan atas), lalu cek file
   .htaccess ikut ter-extract. Kalau tidak ada, aplikasinya tetap jalan tapi
   lapisan pengamannya berkurang.


4. ISI KONFIGURASI
   Di File Manager, klik kanan config.example.php -> Rename -> jadi config.php
   Lalu klik kanan config.php -> Edit, isi:

     'name'     => nama database dari langkah 1
     'user'     => user database dari langkah 1
     'pass'     => passwordnya
     'base_url' => alamat lengkap ke folder ini, tanpa garis miring di akhir,
                   contoh: https://namadomain.com/messi
     'cron_key' => teks acak panjang, ketik asal saja yang panjang dan aneh

   Simpan.


5. BUAT AKUN ADMIN PERTAMA
   Buka di browser:  https://namadomain.com/messi/setup.php
   Isi nama, email, password (minimal 10 karakter).
   Setelah jadi, HAPUS file setup.php lewat File Manager.
   (Dia menolak jalan lagi kalau sudah ada akun, tapi lebih rapi kalau dihapus.)


6. PASANG CRON
   cPanel -> Cron Jobs -> Common Settings: Once Per Hour
   Command:
     /usr/local/bin/php /home/AKUNANDA/public_html/messi/cron/tick.php >/dev/null 2>&1

   Ganti AKUNANDA dengan nama akun cPanel. Kalau tidak yakin path-nya, lihat di
   File Manager bagian atas — di situ tertulis path lengkapnya.


7. TAMBAH ORANG
   Masuk sebagai admin -> di bawah halaman klik "Orang & tim" -> Tambah orang.
   Isi nama, email, tim dan perannya. Passwordnya TIDAK kamu ketik: yang keluar
   adalah link undangan sekali pakai (berlaku 72 jam) — kirim japri, dan orangnya
   yang membuat passwordnya sendiri. Jangan tempel ke space: siapa pun yang bisa
   membaca space itu bisa memakainya.

   Tanggal "Mulai lapor" menentukan sejak kapan orang itu dihitung. Orang baru tidak
   akan pernah ditandai bolos untuk hari sebelum dia bergabung, dan yang belum
   menerima undangannya tidak dihitung sama sekali.

   Lupa password? Tombol "Link buat password baru" di baris orangnya. Tetap tidak
   ada password yang perlu kamu ketik atau kirim.

   PERAN
     Owner    semua, termasuk mengangkat dan mencabut admin. Akun pertama otomatis
              owner, dan selalu harus ada satu.
     Admin    mengurus orang, tim dan pertanyaan. Tidak bisa menyentuh owner maupun
              sesama admin.
     Leader   membaca rekap timnya sendiri. Tidak melihat tim lain sama sekali.
     Pelapor  mengisi laporannya sendiri.


7b. BUAT TIM (kalau lebih dari satu divisi)
   Di halaman yang sama, bagian "Tim". Tiap tim punya pertanyaan, ambang, jam buka
   dan tutup, dan space Google Chat-nya sendiri — jadi HR tidak harus menghitung
   hal yang sama dengan sales, dan pengingatnya masuk ke space masing-masing.
   Satu orang satu tim. Memindahkan orang ke tim lain tidak mengubah rekap yang
   sudah lewat: tiap laporan membawa timnya sendiri.


8. SESUAIKAN PERTANYAANNYA (boleh dilewati)
   Masuk sebagai admin -> di bawah halaman klik "Pertanyaan". Kalau ada lebih dari
   satu tim, pilih dulu timnya di atas — pertanyaan milik tim.
   Yang bisa diubah dari situ, tanpa menyentuh kode:
     - nama tim, yang dicetak di kepala laporan
     - space Google Chat tim itu (kosongkan untuk memakai yang di config.php)
     - daftar channel: kode, nama pendek, nama panjang (tambah / ganti / hapus)
     - batas gantung (3 hari bawaannya), jam buka, jam tutup, maksimal rencana
     - kalimat tiap pertanyaan, contoh isian, dan pesan kalau dikosongkan
     - mematikan pertanyaan yang tidak dipakai
     - kalimat pernyataan di kaki laporan
   Berlaku untuk laporan berikutnya. Laporan yang sudah terkirim tetap terbaca
   dengan setelan yang berlaku saat dikirim — mengubah ambang hari ini tidak
   mengubah arti laporan bulan lalu.


GOOGLE CHAT (boleh dilewati dulu)
---------------------------------
Tanpa ini aplikasinya tetap jalan penuh; bedanya tidak ada pesan otomatis.
Dengan ini, tiap hari kerja space squad dapat tiga pesan:

  09:00  laporan hari ini dibuka + janji siapa saja yang jatuh tempo hari ini
  17:00  pengingat, menyebut siapa yang belum lapor

Cuma dua, dan dua-duanya sekadar mengingatkan orang untuk membuka websitenya.
Rekapnya TIDAK dikirim ke chat: atasan membacanya di tab "Squad" di website,
yang bisa dibuka hari mana saja dan bisa membuka laporan utuh tiap orang —
dua hal yang tidak bisa dilakukan sebuah pesan chat.

Cara pasang, sekitar 2 menit:

 a. Buka space squad di Google Chat
 b. Klik nama space di atas -> Apps & integrations -> Webhooks -> Add webhooks
 c. Beri nama "MESSI" -> Save -> salin URL-nya
 d. Tempel ke 'chat_webhook' di config.php
 e. Buka cek.php -> klik "Kirim pesan uji" -> pesan harus muncul di space

CATATAN PENTING: webhook Google Chat itu memposting ke SATU SPACE, bukan japri
ke tiap orang. Karena itu pesan paginya berisi link biasa, bukan link yang
langsung memasukkan — link semacam itu di space bersama berarti siapa pun di
space bisa masuk sebagai orang lain. Orang masuk dengan password sekali, dan
sesinya bertahan 30 hari, jadi praktis login sebulan sekali.

Ada yang lupa password? Halaman Squad -> tombol "Link masuk" -> kirim JAPRI ke
orangnya. Berlaku 60 menit, sekali pakai.


KALAU ADA MASALAH
-----------------
Layar putih kosong
  Hampir selalu versi PHP. Cek langkah paling atas. Kalau sudah PHP 8, nyalakan
  error log: cPanel -> Metrics -> Errors.

"config.php belum ada"
  Langkah 4 belum dilakukan, atau namanya masih config.example.php.

Bisa masuk tapi halamannya kosong / muter terus
  Biasanya 'base_url' di config.php salah. Harus persis sama dengan alamat yang
  ada di address bar, tanpa garis miring di akhir.

Cron tidak jalan
  Cek path PHP-nya. Sebagian hosting pakai /usr/bin/php atau
  /opt/cpanel/ea-php81/root/usr/bin/php. Lihat di cPanel -> Cron Jobs, biasanya
  ada contohnya di bagian atas halaman.

Mau cek cron tanpa menunggu sejam
  Buka: https://namadomain.com/messi/cron/tick.php?key=CRON_KEY
  Dia akan menulis satu baris ringkasan apa yang barusan dikerjakan.

Pesan otomatis tidak muncul di Google Chat
  Cek dulu tiga baris di cek.php: "Cron terakhir jalan", "Pengingat terakhir
  terkirim", dan "Kesalahan terakhir". Cron meninggalkan satu baris tiap kali
  dijalankan, berhasil maupun tidak ada yang perlu dikerjakan — jadi kalau waktunya
  tidak berubah-ubah, yang bermasalah cron-nya di cPanel, bukan aplikasinya. Kalau pengingatnya berhenti, biasanya dua baris itu sudah menjawab
  kenapa — webhook yang sudah tidak berlaku, atau database yang belum
  dimutakhirkan. Pengiriman yang gagal tidak dicatat selesai, jadi jam berikutnya
  dicoba lagi dengan sendirinya.

  Buka cek.php dan klik "Kirim pesan uji". Dia menguji koneksi ke
  chat.googleapis.com dan mencoba memposting betulan. Dua kemungkinan:
  URL webhook-nya salah salin, atau hosting memblokir koneksi keluar. Kalau
  diblokir, minta hosting membuka port 443 ke chat.googleapis.com.
