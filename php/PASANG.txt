FURA — cara pasang di cPanel
=============================
(Follow Up Report Automation. MESSI — Messenger Screening — adalah modul pertamanya.)

Butuh PHP 8.0 ke atas. Kalau hostingnya masih PHP 7, halamannya akan bilang sendiri
dan memberi tahu cara gantinya. Ganti dulu sebelum lanjut:
cPanel -> Software -> Select PHP Version (atau MultiPHP Manager) -> pilih 8.1 / 8.2.


0. CEK DULU HOSTINGNYA SANGGUP ATAU TIDAK
   Setelah langkah 3 (upload), buka:  https://namadomain.com/messi/cek.php
   Halaman itu memeriksa versi PHP, ekstensi yang dibutuhkan, koneksi database,
   tabel, HTTPS, base_url, dan apakah hosting ini boleh menghubungi Google Chat.
   Setiap yang kurang disebutkan beserta cara membetulkannya, dan di bawahnya ada
   perintah cron yang sudah jadi untuk hosting ini.

   Buka lagi tiap selesai satu langkah. Kalau sudah hijau semua, selesai.
   Setelah akun pemilik dibuat, halaman ini minta login admin dengan sendirinya, dan
   bisa dibuka lagi kapan saja dari menu kanan atas -> Kelola -> Cek sistem.
   Boleh dihapus kalau sudah tidak dipakai.


1. BUAT DATABASE
   cPanel -> MySQL Databases
   - Create New Database: messi
   - Add New User: bikin user + password (simpan passwordnya)
   - Add User To Database: pilih keduanya -> centang ALL PRIVILEGES -> Make Changes
   Catat tiga nama yang jadi, semuanya berawalan nama akun cPanel, contoh:
     database : akunanda_messi
     user     : akunanda_messi
     password : (yang tadi dibuat)


2. BUAT TABELNYA
   cPanel -> phpMyAdmin -> klik database tadi di kiri -> tab Import
   -> Choose File: install.sql -> Go
   Harus muncul sembilan tabel: teams, users, sessions, login_tokens, cycles,
   commitments, settings, login_attempts, job_log

   SUDAH PERNAH PASANG VERSI SEBELUMNYA?
   Upload saja berkas barunya (langkah 3). Databasenya menyusul sendiri: halaman
   pertama yang membutuhkan bentuk baru mengerjakannya, jadi biasanya sudah beres
   sebelum kamu sempat sadar ada yang perlu dikerjakan. Data yang sudah ada tidak
   dihapus, dan tidak ada tombol yang perlu ditekan.

   Kalau karena suatu hal gagal — hak akses database kurang, misalnya — barulah
   halaman "belum siap" muncul seperti dulu, menyebutkan apa yang kurang. Tombol
   manualnya tetap ada di Kelola -> Pemutakhiran database, dan alasannya tercatat
   di Kelola -> Cek sistem.

   (Import ulang install.sql lewat phpMyAdmin juga aman, tapi tidak cukup
   sendirian: kolom baru di tabel yang sudah ada tidak ikut terbuat.)


3. UPLOAD
   cPanel -> File Manager -> masuk ke public_html
   - buat folder: messi
   - masuk ke folder itu -> Upload -> pilih messi-cpanel.zip
   - setelah selesai, klik kanan zip-nya -> Extract
   - hapus zip-nya

   Pastikan "Show Hidden Files" aktif (Settings di kanan atas), lalu cek file
   .htaccess ikut ter-extract. Kalau tidak ada, aplikasinya tetap jalan tapi
   lapisan pengamannya berkurang.


4. ISI KONFIGURASI
   Di File Manager, klik kanan config.example.php -> Rename -> jadi config.php
   Lalu klik kanan config.php -> Edit, isi:

     'name'     => nama database dari langkah 1
     'user'     => user database dari langkah 1
     'pass'     => passwordnya
     'base_url' => alamat lengkap ke folder ini, tanpa garis miring di akhir,
                   contoh: https://namadomain.com/messi
     'cron_key' => teks acak panjang, ketik asal saja yang panjang dan aneh

   Satu lagi yang boleh diisi, boleh dikosongkan:

     'mail_from' => alamat email yang dipakai sistem ini untuk mengirim undangan
                    dan link masuk. Buat dulu akun emailnya di cPanel -> Email
                    Accounts, misalnya fura@namadomain.com, lalu tulis alamat itu
                    di sini. Pakai alamat di domain ini — alamat gmail.com hampir
                    selalu masuk spam.

   Kalau 'mail_from' dikosongkan, aplikasinya tetap jalan penuh; yang berbeda cuma
   undangan dan link masuk harus kamu salin lalu kirim japri sendiri.

   Simpan.


5. BUAT AKUN PEMILIK
   Buka di browser:  https://namadomain.com/messi/setup.php
   Isi nama, email, password (minimal 10 karakter).

   Setelah jadi kamu langsung masuk, dan mendarat di halaman Kelola yang menuntun
   tiga langkah penyiapan: pastikan pertanyaannya, hubungkan Google Chat, undang
   orangnya. Ketiganya ada di bawah ini juga. Begitu ketiganya beres, tuntunan itu
   hilang sendiri dan halamannya jadi beranda biasa.

   Lalu HAPUS file setup.php lewat File Manager.
   (Dia menolak jalan lagi kalau sudah ada akun, tapi lebih rapi kalau dihapus.)


6. PASANG CRON
   cPanel -> Cron Jobs -> Common Settings: Once Per Hour
   Command:
     /usr/local/bin/php /home/AKUNANDA/public_html/messi/cron/tick.php >/dev/null 2>&1

   Ganti AKUNANDA dengan nama akun cPanel. Kalau tidak yakin path-nya, lihat di
   File Manager bagian atas — di situ tertulis path lengkapnya.


7. UNDANG ORANG
   Masuk sebagai admin -> menu di kanan atas (avatar) -> Kelola -> Orang & tim.
   Isi nama, email, tim dan perannya. Passwordnya TIDAK kamu ketik: yang keluar
   adalah link undangan sekali pakai (berlaku 72 jam) — kirim japri, dan orangnya
   yang membuat passwordnya sendiri. Jangan tempel ke space: siapa pun yang bisa
   membaca space itu bisa memakainya.

   SELURUH TIM SEKALIGUS
   Di kotak "atau tempel seluruh timnya sekaligus", tempel satu orang per baris:
     budi@contoh.com
     Sari Wijaya <sari@contoh.com>
   Alamat polos saja boleh — namanya ditebak dari depan tanda @. Yang keluar satu
   tabel: nama, link, dan tombol salin per baris, plus satu tombol untuk menyalin
   semuanya. Baris yang salah ketik dikutip sendiri; yang lain tetap jadi.

   Tanggal "Mulai lapor" menentukan sejak kapan orang itu dihitung. Orang baru tidak
   akan pernah ditandai bolos untuk hari sebelum dia bergabung, dan yang belum
   menerima undangannya tidak dihitung sama sekali.

   Kalau 'mail_from' sudah diisi di config.php, tiap undangan juga langsung dikirim
   ke email orangnya, dan tabelnya menandai mana yang terkirim dan mana yang gagal.
   Yang gagal tetap bisa kamu salin dari situ.

   Lupa password? Tombol "Link buat password baru" di baris orangnya. Tetap tidak
   ada password yang perlu kamu ketik atau kirim.

   Dan orangnya sendiri punya jalan pulang: di halaman masuk ada "Lupa password?".
   Kalau 'mail_from' sudah diisi, link masuk 60 menit dikirim ke emailnya sendiri dan
   kamu tidak perlu mengerjakan apa pun. Kalau belum, permintaannya muncul di atas
   halaman Orang & tim dengan namanya, dan barisnya ditandai "minta link masuk"
   sampai kamu mengeluarkan linknya — yang menolong tetap kamu. Tandanya hilang
   sendiri begitu orangnya berhasil masuk.

   PERAN
     Owner    semua, termasuk mengangkat dan mencabut admin. Akun pertama otomatis
              owner, dan selalu harus ada satu.
     Admin    mengurus orang, tim dan pertanyaan. Tidak bisa menyentuh owner maupun
              sesama admin.
     Leader   membaca rekap timnya sendiri. Tidak melihat tim lain sama sekali.
     Pelapor  mengisi laporannya sendiri.


7b. BUAT TIM (kalau lebih dari satu divisi)
   Di halaman yang sama, bagian "Tim". Tiap tim punya pertanyaan, ambang, jam buka
   dan tutup, dan space Google Chat-nya sendiri — jadi HR tidak harus menghitung
   hal yang sama dengan sales, dan pengingatnya masuk ke space masing-masing.
   Satu orang satu tim. Memindahkan orang ke tim lain tidak mengubah rekap yang
   sudah lewat: tiap laporan membawa timnya sendiri.


7c. MODUL SENDIRI (boleh dilewati)
   Kelola -> Modul. MESSI sudah ada di situ sejak awal, lengkap dengan channel dan
   ambang yang berlaku di timmu — dan sekarang dia salah satu modul, bukan
   satu-satunya.

   MESSI sendiri TIDAK disusun di halaman itu: bentuknya diambil dari halaman
   Pertanyaan, jadi barisnya cuma mengantar ke sana. Dia juga tidak bisa dimatikan
   atau dihapus — dialah satu-satunya modul yang punya layar pengisian, jadi tanpa
   dia tidak ada laporan harian sama sekali.

   PERLU TAHU DULU: modul yang kamu susun sendiri sudah tersimpan utuh, tapi LAYAR
   PENGISIAN HARIANNYA BELUM ADA. Untuk sekarang yang bisa diisi pemain cuma MESSI.
   Jadi silakan menyusunnya, tapi jangan menunggu laporannya masuk.

   Modul baru: beri kode pendek (huruf dan angka, misalnya PRISTA), lalu susun
   pertanyaannya. Enam jenis yang bisa dipakai:

     Angka             tabel baris x kolom. Kolom yang ditandai MERAH adalah yang
                       menyalakan lampu laporan.
     Isian pendek      satu baris.
     Isian panjang     beberapa baris. Bisa diatur supaya langsung diumumkan ke
                       Google Chat begitu diisi.
     Satu angka        tanpa tabel.
     Pilihan           pilih satu dari daftar yang kamu tulis.
     Rencana+tanggal   tiap baris jadi JANJI: di tanggalnya orangnya ditanya "sudah
                       beres?", dan yang lewat tanpa dijawab ditandai tidak ditepati.

   Tiap pertanyaan bisa disetel "ditanyakan selalu" atau "hanya kalau lampunya merah" —
   itulah cara MESSI menanyakan rencana cuma saat ada yang gantung.

   Kode modul tidak bisa diganti setelah dibuat: laporan yang sudah tersimpan menunjuk
   ke kode itu. Modul yang sudah pernah dilaporkan tidak bisa dihapus, hanya dimatikan
   dari katalog — laporan lamanya tetap bisa dibaca.


8. IZIN, CUTI, SAKIT
   Menu kanan atas -> Izin. Untuk sekarang hanya admin dan owner.
   Pilih orangnya, isi tanggal mulai dan selesai, boleh ditambah keterangan
   ("cuti tahunan", "sakit", "dinas luar"). Satu hari saja: isi dua tanggal yang sama.

   Hari yang ditandai izin tidak dihitung "tidak lapor", tidak muncul di "Perlu
   perhatian", dan tidak ditagih bot di pengingat jam tutup. Akhir pekan tidak perlu
   ditandai — memang tidak pernah dihitung. Hari yang laporannya sudah masuk tidak
   ikut ditandai: laporan yang sungguhan selalu menang.

   Bisa untuk hari yang sudah lewat, jadi tanda merah yang tidak adil bisa dibereskan
   belakangan — dan bisa dibatalkan lagi, yang mengembalikan tanda merahnya.

   Leader belum bisa menandai timnya sendiri — kalau ada yang cuti, dia menitipkannya
   ke admin. Izin yang bisa diberikan atasan langsung paling cepat berubah jadi "tolong
   hapus tanda merah saya", dan satu pintu yang jelas lebih mudah dipercaya daripada dua
   yang batasnya kabur.


9. GANTI PASSWORD SENDIRI
   Menu kanan atas -> Akun. Di situ tiap orang bisa mengganti namanya dan
   passwordnya sendiri — password sekarang ikut ditanya, dan begitu berganti, semua
   perangkat lain yang masih masuk dikeluarkan.

   Peran, tim dan tanggal mulai ditampilkan di situ tapi tidak bisa diketik: ketiganya
   menentukan orang itu muncul di rekap siapa, jadi yang mengubahnya admin.


10. SESUAIKAN PERTANYAANNYA (boleh dilewati)
   Menu kanan atas -> Kelola -> Pertanyaan. Kalau ada lebih dari satu tim, pilih
   dulu timnya di atas — pertanyaan milik tim.
   Yang bisa diubah dari situ, tanpa menyentuh kode:
     - nama tim, yang dicetak di kepala laporan
     - space Google Chat tim itu (kosongkan untuk memakai yang di config.php)
     - daftar channel: kode, nama pendek, nama panjang (tambah / ganti / hapus)
     - batas gantung (3 hari bawaannya), jam buka, jam tutup, maksimal rencana
     - kalimat tiap pertanyaan, contoh isian, dan pesan kalau dikosongkan
     - mematikan pertanyaan yang tidak dipakai
     - kalimat pernyataan di kaki laporan
   Berlaku untuk laporan berikutnya. Laporan yang sudah terkirim tetap terbaca
   dengan setelan yang berlaku saat dikirim — mengubah ambang hari ini tidak
   mengubah arti laporan bulan lalu.


GOOGLE CHAT (boleh dilewati dulu)
---------------------------------
Tanpa ini aplikasinya tetap jalan penuh; bedanya tidak ada pesan otomatis.
Dengan ini, tiap hari kerja space tim dapat dua pesan:

  09:00  laporan hari ini dibuka + janji siapa saja yang jatuh tempo hari ini
  17:00  pengingat, menyebut siapa yang belum lapor — yang sedang izin tidak disebut

Kalau jam 17 terlewat karena cron-nya tidak jalan jam itu, pengingatnya menyusul di
jam berikutnya, dengan kalimat yang mengakui jam tutupnya sudah lewat.

Cuma dua, dan dua-duanya sekadar mengingatkan orang untuk membuka websitenya.
Rekapnya TIDAK dikirim ke chat: atasan membacanya di tab "Tim" di website,
yang bisa dibuka hari mana saja dan bisa membuka laporan utuh tiap orang —
dua hal yang tidak bisa dilakukan sebuah pesan chat.

Cara pasang, sekitar 2 menit:

 a. Buka space tim di Google Chat
 b. Klik nama space di atas -> Apps & integrations -> Webhooks -> Add webhooks
 c. Beri nama "FURA" -> Save -> salin URL-nya
 d. Tempel ke halaman Kelola -> Pertanyaan -> "Space Google Chat tim ini"
    (atau ke 'chat_webhook' di config.php kalau cuma ada satu tim)
 e. Di halaman yang sama, klik "Simpan lalu kirim pesan tes" -> pesan harus muncul
    di space. Kalau gagal, halamannya mengatakannya seketika — bukan besok jam buka.

CATATAN PENTING: webhook Google Chat itu memposting ke SATU SPACE, bukan japri
ke tiap orang. Karena itu pesan paginya berisi link biasa, bukan link yang
langsung memasukkan — link semacam itu di space bersama berarti siapa pun di
space bisa masuk sebagai orang lain. Orang masuk dengan password sekali, dan
sesinya bertahan 30 hari, jadi praktis login sebulan sekali.

Ada yang lupa password? Kalau 'mail_from' sudah diisi di config.php, dia cukup menekan
"Lupa password?" di halaman masuk dan link masuknya dikirim sendiri ke emailnya. Kalau
belum: Kelola -> Orang & tim -> tombol "Link masuk" di barisnya -> kirim JAPRI ke
orangnya. Berlaku 60 menit, sekali pakai. Namanya sudah menunggu di atas halaman itu
kalau dia sudah menekan "Lupa password?".


OWNER SENDIRIAN DAN LUPA PASSWORD
---------------------------------
Kalau ada admin lain, minta dia menekan "Link buat password baru" di barismu. Kalau
tidak ada siapa pun, linknya dibuat sendiri dari database — satu kali, lewat phpMyAdmin:

  cPanel -> phpMyAdmin -> pilih database -> tab SQL -> tempel, ganti emailnya:

    INSERT INTO login_tokens (token, user_id, kind, expires_at)
    SELECT SHA2(CONCAT(RAND(), UUID()), 256), id, 'invite',
           DATE_ADD(UTC_TIMESTAMP(), INTERVAL 1 HOUR)
      FROM users WHERE email = 'email-kamu@contoh.com';

    SELECT token FROM login_tokens ORDER BY id DESC LIMIT 1;

  Lalu buka:  https://namadomain.com/messi/undang.php?t=TOKEN_YANG_TADI

Halaman itu yang biasa dipakai orang baru membuat passwordnya, dan dia mengerjakan hal
yang sama di sini: kamu mengetik password baru, lalu langsung masuk. Linknya berlaku
satu jam dan hangus begitu dipakai.

Setelah masuk, angkat satu admin lagi lewat Kelola -> Orang & tim. Kali berikutnya
cukup dia yang menekan tombolnya, tanpa menyentuh database.


KALAU ADA MASALAH
-----------------
Layar putih kosong
  Hampir selalu versi PHP. Cek langkah paling atas. Kalau sudah PHP 8, nyalakan
  error log: cPanel -> Metrics -> Errors.

"config.php belum ada"
  Langkah 4 belum dilakukan, atau namanya masih config.example.php.

Bisa masuk tapi halamannya kosong / muter terus
  Biasanya 'base_url' di config.php salah. Harus persis sama dengan alamat yang
  ada di address bar, tanpa garis miring di akhir.

Cron tidak jalan
  Cek path PHP-nya. Sebagian hosting pakai /usr/bin/php atau
  /opt/cpanel/ea-php81/root/usr/bin/php. Lihat di cPanel -> Cron Jobs, biasanya
  ada contohnya di bagian atas halaman.

Mau cek cron tanpa menunggu sejam
  Buka: https://namadomain.com/messi/cron/tick.php?key=CRON_KEY
  (CRON_KEY itu rahasia seperti password. Kalau pernah tertempel di chat atau di
  mana pun yang bisa dibaca orang lain, ganti isinya di config.php.)
  Dia akan menulis satu baris ringkasan apa yang barusan dikerjakan.

Pesan otomatis tidak muncul di Google Chat
  Cek dulu tiga baris di cek.php: "Cron terakhir jalan", "Pengingat terakhir
  terkirim", dan "Kesalahan terakhir". Cron meninggalkan satu baris tiap kali
  dijalankan, berhasil maupun tidak ada yang perlu dikerjakan — jadi kalau waktunya
  tidak berubah-ubah, yang bermasalah cron-nya di cPanel, bukan aplikasinya. Kalau pengingatnya berhenti, biasanya dua baris itu sudah menjawab
  kenapa — webhook yang sudah tidak berlaku, atau database yang belum
  dimutakhirkan. Pengiriman yang gagal tidak dicatat selesai, jadi jam berikutnya
  dicoba lagi dengan sendirinya.

  Buka Kelola -> Cek sistem dan klik "Kirim pesan uji". Dia menguji koneksi ke
  chat.googleapis.com dan mencoba memposting betulan. Dua kemungkinan:
  URL webhook-nya salah salin, atau hosting memblokir koneksi keluar. Kalau
  diblokir, minta hosting membuka port 443 ke chat.googleapis.com.
